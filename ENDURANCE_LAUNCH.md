# Как запустить Endurance (TU Overlays)

Модуль состоит из 4 веб-страниц + десктоп-приложения, которое читает телеметрию iRacing.
Живые данные (текущий стинт, время выезда из пита и т.д.) появляются **только** когда десктоп-
приложение запущено и страница подключена к нему напрямую (режим "local"). Без него доступно
только планирование стинтов (режим "cloud"/team).

## 0. Предварительно

- Скачать и установить десктоп-приложение TU Overlays:
  `download.html` → кнопка `.exe`/`.zip` (репозиторий `github.com/AVAILOFF/TUOverlays/releases/latest`).
- Запустить iRacing и десктоп-приложение — оно поднимает локальный сервер на
  `http://localhost:3000` (WebSocket), через который страницы получают телеметрию.

## 1. Четыре страницы

| Страница | Файл | Назначение |
|---|---|---|
| Кабинет | `endurance.html` | Планирование стинтов (вкладка «Стинты»), настройки оверлея, статус Live |
| OBS-оверлей | `endurance-overlay.html` | То, что реально добавляется в OBS как Browser Source |
| Превью оверлея | `endurance-overlay-preview.html` | Просмотр оверлея в iframe + готовые ссылки для копирования в OBS |
| Race View | `endurance-view.html` | Публичная страница расписания/статуса для зрителей и тиммейтов |

## 2. Соло-запуск (стример сам ведёт заезд)

1. Запустить iRacing + десктоп-приложение TU Overlays на этом же ПК.
2. Открыть Кабинет: `endurance.html?wsUrl=http://localhost:3000`
   (без параметра `wsUrl` Кабинет по умолчанию уходит в облачный режим, а не в локальный —
   параметр нужен явно).
3. Ввести пароль подключения (`enduranceAuth`) — тот же, что задан в десктоп-приложении.
4. На вкладке «Стинты» собрать план: пилоты, стинты, топливо, пит-стопы.
5. Открыть «Превью оверлея» в навигации Кабинета (`endurance-overlay-preview.html`) —
   там будет готовая ссылка вида `.../endurance-overlay.html` для копирования.
   - Заметь: `endurance-overlay.html` **сам по себе**, без параметров, уже пытается
     подключиться к `http://localhost:3000` — если оверлей и приложение на одном ПК,
     параметр `wsUrl` можно вообще не указывать.
6. В OBS: Источники → Browser Source → вставить скопированную ссылку, выставить размер холста,
   включить «Обновлять браузер при активации сцены».
7. Проверить, что в Кабинете статус подключения — «authed»/подключено, и что после выезда
   пилота из питов в Кабинете и на оверлее появляется актуальное время старта стинта.

Тестовый режим без реальной телеметрии: `endurance-overlay.html?test=1` (или через кнопку
«Test» на странице превью) — покажет оверлей на демо-данных, полезно для настройки макета
до выхода на трассу.

## 3. Командный запуск (совместное планирование / зрители)

Облачный режим (`?team=...`) даёт **только** синхронизацию плана и настроек оверлея между
устройствами — живой телеметрии в нём нет (её отдаёт исключительно локальное подключение
к десктоп-приложению).

1. В Кабинете без параметров (`endurance.html`) нажать «Создать команду» — сгенерирует
   `teamId` и допишет его в адресную строку как `?team=<id>`.
2. Задать пароль команды.
3. Этой ссылкой (`endurance.html?team=<id>`) поделиться с со-пилотами — они смогут вместе
   редактировать план стинтов, введя тот же пароль.
4. Зрителям/команде — ссылка на Race View: `endurance-view.html?team=<id>`, покажет
   расписание и (если кто-то из команды параллельно запустил десктоп-приложение и Overlay
   в local-режиме) актуальный статус.

## 4. Быстрая шпаргалка по URL-параметрам

- `wsUrl` — адрес локального WebSocket десктоп-приложения (по умолчанию у оверлея
  `http://localhost:3000`, у Кабинета — пусто → облачный режим).
- `team` — id команды для облачного режима (Кабинет, Race View).
- `test=1` / `demo=plan` — демо-данные оверлея без реального подключения.
- `layout=timeline|table|current|next` — принудительный макет оверлея.
- `speed` — множитель скорости для демо-режима (ускоренная прокрутка времени).
