# Таблицы стинтов (TU Overlays)

Инструмент из трёх частей:

| Что | Адрес | Кто видит |
|---|---|---|
| Публичная таблица | `/s/<id>` | любой по ссылке; `noindex`, в поиск не попадает |
| Панель | `/stints-admin` | только по личному ключу |
| API | `/api/stints`, `/api/boards`, `/api/keys` | чтение таблицы открыто, запись — по ключу |

Модуль полностью отдельный: `endurance.html` и `/endurance-assets/` он не трогает.

## 1. Что нужно настроить в Vercel (один раз)

1. **Хранилище.** Проект → Storage → Upstash Redis (бесплатный тариф) → Connect.
   Интеграция сама добавит переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN`
   (у маркетплейсной версии — `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`;
   код понимает оба варианта).
2. **Ключ владельца.** Settings → Environment Variables → `STINTS_OWNER_KEY`,
   значение — длинная случайная строка. Это ваш вход в панель.

Без этих переменных API отвечает `503` и панель честно говорит, что хранилище не
настроено — как и `middleware.js` для админки благодарностей, он не открывается
«наполовину».

Генератор ключа:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

## 2. Как это работает

**Владелец** заходит на `/stints-admin`, вводит `STINTS_OWNER_KEY` (ключ ложится
в `localStorage` браузера) и создаёт таблицу. Внутри таблицы три вкладки:

- **Стинты** — гонка, пилоты, строки стинтов. Время вводится как `55:00` или
  `1:01:00`. Колонки «Старт» и «Конец» — это смещения от старта гонки; под ними
  показывается время суток, если задан «Старт гонки». «Конец» можно править —
  меняется длительность стинта.
  - Кнопка «Пересчитать старты подряд» выстраивает весь план цепочкой: каждый
    стинт начинается там, где закончился предыдущий, плюс его пит-стоп.
  - Кнопка «Пересчитать по-своему…» — то же, но с выбором: с какого стинта
    начинать (более ранние не трогаются), с какого смещения, и можно навязать
    общую длительность и/или пит всем пересчитываемым стинтам.
  - Флажок «Автопересчёт стартов после правок» (хранится в браузере, не в
    таблице): пока включён, «Старт» только для чтения, а любое изменение
    длительности, «Конца» или пита сразу перестраивает цепочку.
  - Кнопка «Импортировать» в самом верху вкладки берёт ссылку на публичный
    Google Таблицы-документ с журналом стинтов (доступ — «Все, у кого есть
    ссылка») и подставляет из него пилотов и строки стинтов; заменяет то, что
    было в форме, но ничего не сохраняет — это по-прежнему делает «Сохранить».
    Названия колонок ищутся по смыслу (`Driver`/«Пилот», `Stint
    length`/«Длительность», `Pit-stop length`, `Laps`/«Круги», `Refuel`,
    `Comments`/«Заметка», `Stint Start Time`/«Начало стинта»), лишние
    аналитические колонки игнорируются, а старт каждого стинта пересчитывается
    цепочкой — часы в середине таблицы не используются, чтобы не спотыкаться о
    полночь. Единственное время суток, которое импорт всё-таки забирает, —
    начало первого стинта: оно ложится в «Старт гонки», иначе смещения были бы
    верные, но весь план уезжал бы на столько, на сколько «Старт гонки» в
    таблице расходился с первым стинтом. Если промежутки между стартами в
    Google-таблице неравномерные, импорт об этом предупреждает.
- **Вид** — оформление публичной страницы: колонки и их порядок, тема, акцент,
  плотность, формат времени, подсветка текущего стинта, автообновление и прочее.
  Справа — настоящая публичная страница в `<iframe>`, которая перерисовывается на
  каждое изменение. «Опубликовать» сохраняет, «Отменить изменения» возвращает
  последнюю опубликованную версию.
- **Доступ** — выдача личных ключей.

**Приглашённый** получает ссылку вида `https://tuoverlays.xyz/stints-admin#k=<ключ>`.
Ключ в `#фрагменте` — браузер такие не отправляет на сервер, поэтому он не оседает
в логах и в заголовке `Referer`. Панель забирает его из адреса, кладёт в
`localStorage` и вычищает адресную строку.

Права ключа: **«только стинты»** — правит данные, но не оформление и не доступы;
**«стинты и оформление»** — плюс вкладка «Вид». Создавать и удалять таблицы, а
также выдавать ключи может только владелец.

Ключ хранится у нас **только в виде SHA-256**. Посмотреть выданный ключ повторно
нельзя — можно отозвать и выпустить новый. Отзыв срабатывает мгновенно.

## 3. Хранение

Один документ на таблицу:

```
stints:board:<id>   { title, meta, data, view, access, rev, updatedAt, updatedBy }
stints:index        список таблиц для владельца
stints:key:<hash>   к каким таблицам даёт доступ конкретный ключ
```

Публичное чтение отдаёт всё, кроме секции `access`, поэтому хэши ключей наружу не
попадают, даже несмотря на то, что ссылка на таблицу открыта.

Запись идёт с номером ревизии: если двое правят одновременно, второй получит
«таблицу уже изменили, обновите страницу», а не молча затрёт чужую работу.

Поля названы так же, как в собранном модуле Endurance (`driverId`,
`startOffsetSec`, `plannedDurationSec`, `pitStopDurationSec`), чтобы позже можно
было вставить план из кабинета без конвертера.

## 4. Локальная разработка

Статический сервер отдать `/api` не может, поэтому есть маленький стенд:

```bash
node scripts/dev-server.mjs
```

Поднимает `http://localhost:8787` с теми же маршрутами, включая rewrite `/s/:id`.
Без переменных Upstash данные пишутся в файлы в `.stints-dev/` (в `.gitignore`),
ключ владельца по умолчанию — `dev-owner-key`. Чтобы задать свой:

```bash
STINTS_OWNER_KEY=my-key node scripts/dev-server.mjs
```

Сам стенд в деплой не попадает — он перечислен в `.vercelignore`.

## 5. Файлы

```
stints.html            публичная страница
stints-admin.html      панель
css/tu-stints.css      оформление публичной страницы (все темы)
css/tu-stints-admin.css оформление панели
js/tu-stints.js        рендер таблицы + автообновление + режим предпросмотра
js/tu-stints-admin.js  логика панели
api/stints.js          чтение и запись таблицы
api/boards.js          список, создание, удаление таблиц
api/keys.js            выпуск и отзыв ключей
api/sheet-import.js    импорт стинтов из Google Таблиц
api/_lib/*.js          хранилище, авторизация, схема, HTTP-помощники
```

Обе страницы добавлены в `scripts/build.mjs`, поэтому при деплое их CSS и JS
вклеиваются внутрь HTML — как и на остальных страницах сайта.
